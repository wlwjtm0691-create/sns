# 블로그 작성 절차

이 스킬은 새 글 작성, 리서치만 수행, 기존 글 수정, 최신화 요청을 구분해 해당 범위의 절차를 실행한다. 일반적인 설정 문의에는 글 작성 절차를 실행하지 않는다.

## 새 글 전체 작성
1. config/editorial.md와 templates/article.md를 읽는다.
2. 사용자 입력에서 주제, 독자, 플랫폼, 분량을 추출한다. 빠진 항목은 편집 기준의 기본값을 쓴다. 핵심 주제 해석이 달라질 수 있을 때만 질문한다.
3. posts/의 기존 글을 살펴 주제 중복과 내부 링크 기회를 확인한다.
4. posts/YYYY-MM-DD-slug/ 작업 폴더를 만들고 brief.md에 주제 해석, 독자, 핵심 질문, 범위를 기록한다.
5. 웹에서 조사한다. 검색 결과만으로 판단하지 말고 주요 원문을 연다. 핵심 주장별로 근거, 원문 링크, 발행일, 확인일, 주의점을 research.md에 기록한다. 최신성이 중요한 사실은 기준일을 명시한다.
6. 조사 근거에 맞춰 목차와 논지를 draft.md에 작성한다. 사실과 의견을 분리하고 출처 링크를 가까이 둔다.
7. 원문과 대조해 주장, 수치, 날짜, 고유명사, 인용을 확인한다. 도입, 논리 흐름, 중복, 문장, 맞춤법도 검수한다. 결과와 수정 사항을 review.md에 기록하고 아래 체크리스트를 완료한다.
8. 수정한 최종 원고가 draft.md에 있는지 확인한다. 검수 항목을 모두 완료한 뒤 python scripts/validate_article.py "posts/YYYY-MM-DD-slug" --promote를 실행한다.
9. 승격이 성공하면 python scripts/validate_article.py "posts/YYYY-MM-DD-slug"를 실행한다. 통과한 경우에만 완료를 보고한다. 실패하면 오류를 해결하고 다시 검사한다.
10. 사용자에게 final.md 경로, 제목, 소개문, 제목 후보, 핵심 검색어, 출처 및 남은 한계를 알려준다.

## 다른 요청의 범위
- “리서치만”: brief.md, research.md를 만들거나 갱신한다. 초안 승격을 하지 않는다.
- “수정”: 지정한 기존 글을 편집하고 검수 기록을 갱신한다. 기존 final.md는 덮어쓰지 않는다. 새 버전은 새 날짜/버전 폴더에 저장한다.
- “최신화”: 변동 사실을 다시 조사하고 변경 사항과 확인일을 기록한 새 버전을 만든다.
- “설정 변경”: 편집 기준·템플릿·지침 파일만 수정한다.

## 검수 체크리스트 형식
review.md에 아래 항목을 그대로 넣고, 각 항목을 확인한 뒤 [x]로 표시한다. 수행하지 않은 검사를 완료로 표시하지 않는다.

- [ ] 조사 출처의 원문을 확인했고 핵심 주장과 일치함
- [ ] 수치, 날짜, 인용, 고유명사를 출처와 대조함
- [ ] 출처 없는 주장을 삭제하거나 불확실성 표시함
- [ ] 문체, 구조, 중복, 맞춤법을 검수함
- [ ] 최종 원고와 출처 링크를 점검함

스크립트는 이 체크리스트의 완료 여부와 파일 형식을 확인한다. 체크 표시만으로 사실 검증이 보장되지는 않으므로, 검수 기록에는 확인한 출처와 수정 사항도 적는다.
